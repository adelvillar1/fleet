# The skill chains

The skills compose. Each chain stops at its requested outcome; an
authorized workflow continues without re-approval. The session cycle
is the spine; the others hang off it.

## The session cycle

```
warmup → plan → build → recap
```

warmup situates the session (one bounded pass: git state, the newest
recap's summary, plan status lines, the ledger's open count — a compact
report ending with the ask; it never executes what it finds open); plan
drafts the contract (the acceptance criteria, the gate);
build lands it (the gate green, the commits); recap closes the loop
(the criteria walked, the docs proposed). The cycle repeats; each
turn's context is the last recap.

## The review chains

- **think → check**: the plan is drafted (think), implemented after
  approval, then reviewed before merging (check) — the diff against
  the project's constraints, the verification, the ship decision.
- **hunt → check**: the root cause is found (hunt), the fix applied,
  then the change reviewed (check) — a fix and its review are one
  task's two halves.
- **read → learn → write**: sources are read (read), synthesized
  (learn), polished (write) — the research chain.

## The learning chains

- **measure → plan → teach**: the probe brackets the learner's
  current understanding (measure), the minimal tree is drawn (plan),
  the teaching moves one checked step at a time (teach). The goal's
  self-evidence is the terminal condition.
- **teach → practice**: the teaching's steps are exercised in
  separate problem sessions; the knowledge must come to mind
  unnamed.
- **the friction feeds**: a lesson's friction names a lack; the
  lack's kind picks the surface — persona, skill, tool, workflow —
  and the proposal lands through that surface's gate.

## The feed chains

- **a confusion → the demand map**: the learning rows' confusions
  are demand classes the beats read.
- **a recurring confusion → a shape proposal**: the clustering
  beat's output lands as an improve proposal, owner-applied.
- **a recurring procedure → a workflow**: the cron's scheduled
  runs, the plan templates, the huddle workflows.
- **a needed expertise → a persona**: the roles module; the
  huddle's author_persona precedent — a domain with no one in it
  gets a purpose-built persona.
- **a repeated procedure → a skill**: the self-authoring drafter
  files the owner-gated draft.

## The principle

The chains are the skills' composition order, not a workflow engine:
each skill stops at its outcome, and the next begins where the last
ended. The authorization to continue is the task's; the chain is the
map, not the permission.
