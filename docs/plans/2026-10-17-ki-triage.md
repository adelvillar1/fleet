# Plan: KI ledger triage

## Context

`docs/known-issues.md` is Fleet's shared ledger, holding 214 rows as of this plan, of which 84 are open. Many of those rows are fixable inside Fleet's own source tree; others are owner decisions, external-repo actions, or deferred work that the ledger already classifies correctly.

This plan batches the open rows by action class and defines verifiable closure for each batch. The ledger is the source of truth; this plan ensures every open row lands in exactly one batch and that batch's exit criteria name it.

## Approach

Three sequential batches, each independently closable:

1. Defects and gaps inside the crate — Rust-source fixes plus regression tests.
2. Docs, surfaces, and process gaps — markdown corrections, TUI/rendering fixes, CLI/docs corrections, and test-harness flake mitigation.
3. Decisions and external work — owner decisions on ecosystem repos, environmental items, and deferred items correctly out of scope for Fleet's code.

Rows already marked "noted" or "informational" stay in place unless they have an actionable fix; then they move to the appropriate batch.

High-level steps:

1. Parse `docs/known-issues.md`, enumerate open rows, assign each to a batch.
2. For batch 1: implement Rust fixes, add regression tests, update ledger rows with evidence and status.
3. For batch 2: fix docs/surfaces/CLI issues, add width/wrapping tests where applicable, update ledger rows.
4. For batch 3: annotate ledger rows with decision-needed or external markers; do not change source.
5. Run `cargo test --all-targets` green; run ledger parser script; update plan status to completed.

## Use cases

- [ ] A: An open defect row is closed only after a regression test pins the fixed behavior and the ledger row cites that test.
- [ ] B: An open gap row is closed only after the missing capability is implemented or explicitly deferred with reason.
- [ ] C: An open improvement row is closed only after the improvement lands or is moved to a later slice with rationale.
- [ ] D: A row requiring an owner decision is not left open without the decision named in the ledger.
- [ ] E: A row requiring external-repo action is not left open without a reproduction or issue reference.

## UX routes

None — this is a ledger triage and internal-fix plan. No user-visible UI contract changes.

## Acceptance criteria

- [ ] C0: The ledger parser script reports zero rows missing an ID, severity, status, or next-action field.
- [ ] C1: Every batch 1 KI named in the plan is closed-fixed in `docs/known-issues.md` with evidence updated, or moved to batch 3 with a stated reason.
- [ ] C2: `cargo test --all-targets` is green after batch 1 source changes, with no new warnings.
- [ ] C3: Every batch 2 KI named in the plan is closed-fixed in `docs/known-issues.md` with evidence updated, or moved to batch 3 with a stated reason.
- [ ] C4: The TUI renders without clipping at 80 columns and 120 columns on the fixed-width surfaces named in batch 2 rows.

- [ ] C6: README, feature docs, and architecture docs cite the actual source layout, CLI forms, and router lineage where batch 2 touches them.
- [ ] C7: Every batch 3 KI is marked with the exact decision needed or the external repo/issue in `docs/known-issues.md`.

## Risks

- Batch 1 touches many modules; merge conflicts with parallel slices are possible. Mitigate by gating frequently and keeping changes narrow.
- Some "improvement" rows are genuinely deferred to later slices; closing them as deferred requires explicit rationale so they are not forgotten.
- The ledger is long; manual row updates risk markdown table corruption. Mitigate with the parser script in verification.

- KI-220 — the write guard refuses a live roster model named in a doc's
  backticks. Fixed: a token whose lowercase form matches a roster model
  is a wire identifier, not drift. Pinned by
  `a_live_roster_model_is_a_name_the_guard_does_not_police`.
- KI-222 — the 638-entry corpus exceeds the embed's inherited 60-second
  default. Fixed: the rebuild's one-shot embed passes the longer timeout
  the kwarg already accepts (600s), so the ceiling was a default, not a
  wall.
- KI-223 — the corpus refresh's change detection is poisoned by the
  cwd. Fixed: the chunk key is the source's absolute path, the one
  cwd-independent name it has. Verified by deriving the same source from
  two working directories.
- KI-225 — a job's declared sources include files that do not exist.
  Fixed: the refresh names them as `missing_sources` in its report
  instead of deriving silently from what remained.
- KI-226 — the write guard blocks ordinary Python drivers. Fixed on both
  scopes the row named: the guard polices the tree its vocabulary came
  from (a path outside it is not project code), and a Python file's
  capitalized builtins are the language's names, not this project's
  drift. Pinned by `an_ordinary_python_driver_is_writable_as_written`.

choice between the cron jobs invoking the capability the driver session

owner's to make. The remaining batch-3 rows name their own decision or
external repo in their next-action column, as the ledger's rule requires.

The 25 remaining batch-1 rows and 31 batch-2 rows are the next passes'
work; each stays open with its batch tag until its fix lands with
