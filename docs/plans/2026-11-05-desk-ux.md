# Plan: the desk, as a first-class surface

## Context

The desk shipped on 2026-11-04 as a data model with a face that renders
(`docs/plans/2026-11-04-desk.md`, `status: completed`). It renders *wrong*, and
the reasons are measurable rather than aesthetic. The owner asked for a deep
dive on the desk surface and a design that makes it first-class.

This plan answers a measured audit of the shipped face. Every finding below was
read out of `src/gui/assets/app.js`, `src/gui/assets/app.css`, live
`/api/desk` JSON on a scratch home, or measured in Chromium — not inferred from
the plan that preceded the build.

**The headline defect: the desk's stylesheet was never merged.** `paintDesk` and
`paintDeskProject` (`app.js:9995-10300`) emit `hsection`, `hrow-name`, `chip`,
`chip-ok`, `chip-warn`, `chip-down`, `serif`, `mono`, `sub`. The mockup's
`mockup.css` — whose own header says it was "hand-copied from app.css so the
translation is a translation and not a reinvention" — was never applied.
Measured with a `document.styleSheets` walk, matching each element against every
rule:

```
.chip        -> ["*","*",".chip"]        (exists)
.chip-ok     -> ["*","*",".chip"]        (no .chip-ok rule exists)
.chip-warn   -> none                      (no .chip-warn rule exists)
.chip-down   -> none                      (no .chip-down rule exists)
.hsection    -> ["*","*"]                 (no rule exists)
.hrow-name   -> ["*","*"]                 (no rule exists)
.serif       -> ["*","*"]                 (no rule exists)
```

`grep desk src/gui/assets/*.css` returns **0 hits**. So every "chip" is a plain
run of text in the same grey, every "section head" collapses into the body, and
the five stages of the stage strip concatenate into one mashed run —
`sections[1].heading` literally reads
`"claims · doneoutline · donereview · donerender · done"`.

**Two corrections to my own first audit pass, recorded because a plan built on a
stale claim is worse than no plan:**

- **`stages` does not serialize as two-element arrays.** I first recorded
  `Vec<(Stage, StageState)>` as emitting `["claims", {"state":"done"}]`. The live
  API returns objects: `{"stage":"claims","state":"done","reason":null}`. The
  face must read `stage`/`state`/`reason` keys.
- **`delete_project` exists.** I first recorded "no `delete_project` in `src/`,
  no route". `src/desk.rs:358` defines it and it is tested
  (`src/desk.rs:2250`). What is missing is the *route* and the *face control* —
  the capability is unwired, exactly like `run_stages`.

## Direction lock

**The desk's job is to be believed, not to be looked at.** Everything here
serves one sentence the owner can act on: *what stands between this deliverable
and its end, and what do I do about it.* A surface that renders a refusal below
the fold, with no action beside it, has not done the job even if every pixel is
correct.

**The blocking state owns the top of the screen.** Refusals are the desk's whole
reason for existing; they go first, under the stage rail, not last under the
draft.

**The way out is always reachable.** Any screen with a primary action pins that
action to the viewport. A button 552px below the fold on a 700px screen is not a
control, it is a decoration.

**Colour carries state, and it is backed by a word.** A red pill says *why*. The
empty shell's failure was colour that never arrived; the fix is not "more
colour", it is colour that means one thing each, plus the word so colour is
never the only carrier.

**Tokens are copied, not invented.** The mockup copies `app.css`'s real themes.
The translation into app.css is a translation. A new token is a decision, not a
side effect.

**Fields the API computes get a home, or get deleted.** `coverage`, `overlap`,
`figures` and `escalated` are computed server-side at real cost. A field with no
surface is either a missing surface or a calculation nobody wanted.

## The design

`docs/plans/mockups/2026-11-05-desk-ux/desk.html` — one navigable page, 4 states
× 3 widths × 4 themes = 48 cells, each addressable:

```
?state=<shelf|deliverable|composer|empty>&w=<1440|1024|390>&theme=<paper|console|graphite|contrast>
```

**The shelf** is three zones: a left rail (all / needs you / by project / by
state), the shelf itself, and a standing right column, *what the desk owes you*,
which lists the refusals and gaps across every deliverable with a jump action.
Each shelf row carries its own state: a red left edge for refused, accent for
running, none for clean, and pills that name the state in words. Evidence reads
as one proportion bar (asserted / contested / unsourced) rather than three
identical chips. Coverage is a five-segment meter with its reason spelled out,
and the `escalated` flag is a pill. Empty and unbound desks are visibly
first-class-but-unstarted, not silently identical to finished ones.

**The deliverable** puts the stage rail at the top as five separate stacked
nodes — each with its own bead, its own fill (green done, red refused, accent
running) and its own label. Immediately below it, the gate: each refusal is a
row carrying its own assertion, the nearest sentence the extractor *did* find
with its overlap score (0.41), the canonical figure, and a fix action (*reword
it*, *add the figure*). Then the review, where every claim sits beside the exact
sentence it was read from, with its kind, confidence and source path. Outline
gaps render as a dashed hole in the outline itself, with the action that closes
them. The draft marks the refused figure inline. The end band pins to the
viewport bottom and says plainly *not ready to end — 2 refusals stand and
coverage is 2 of 5*.

**The composer** is a real form: required fields marked, per-source kind chips
(file / fact / url), a source list with remove, a shape select, a submit row that
names the fields still missing, and a pinned submit. Beside it, the four things
that will happen on submit, in the owner's language.

**The empty state** explains the benefit before the mechanism in three steps.

## Precedents this plan answers

- `docs/plans/2026-11-04-desk.md` — the build this repairs. Its C1 promised
  mockups "in the app's own tokens" and its `## The design` promised the three
  zones; the tokens and the zones both stopped at the mockup. **The difference
  here is that this plan's first criterion is the CSS translation itself**, not
  another mockup approval.
- `docs/plans/2026-11-04-huddles-ux.md` — the same "surface shipped, UX absent"
  shape, and the precedent for how it was closed: mockups measured, then a
  harness that pins the states.
- `memories/huddle-mockups-measured-not-read.md` — verify by in-page
  measurement. This session cannot see a PNG, so measurement is the only
  instrument; it is also the better one.
- KI-400 (a row builder returning a bare node where the pane expected
  `[[label, node]]` sections) — the lesson that a row that renders fine can
  still be unpressable, so this plan pins the *press*, not the render.

      bare `*` rule. *This is the headline defect and the first thing that
      lands.*

## Risks

- **The translation is bigger than it looks.** The desk's markup was written
  against a stylesheet that never arrived, so it was never *constrained* by one.
  Some of its structure will need to change shape as the CSS lands, not just gain
  rules. Budget for rewriting the painters rather than only adding rules.
- **C10's routes are the load-bearing increment.** Without a face-side walk the
  end button cannot honestly be a control, and the surface stays a viewer. If
  C10 slips, C6 still applies but must say *not ready* rather than *end*.
- **A pinned action band can cover content.** Sticky furniture eats viewport on
  a 700px screen. The measurement must assert that the last section is not
  permanently hidden behind the band.
- **Copy that flatters.** "It reads the sources and refuses to call the work
  done" is a promise about behavior. Where the face cannot yet keep it (no walk
  route), the copy must not imply it can.
