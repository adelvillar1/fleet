# Plan: the desk, as a first-class surface

## Context

The desk shipped on 2026-11-04 as a data model with a face that renders
(`docs/plans/2026-11-04-desk.md`, `status: completed`). It renders *wrong*, and
the reasons are measurable rather than aesthetic. The owner asked for a deep
dive on the desk surface and a design that makes it first-class.

This plan answers a measured audit of the shipped face. Every finding below was
read out of `src/gui/assets/app.js`, `src/gui/assets/app.css`, live
`/api/desk` JSON on a scratch home, or measured in Chromium — not inferred from
the plan that preceded the build.

**The headline defect: the desk's stylesheet was never merged.** `paintDesk` and
`paintDeskProject` (`app.js:9995-10300`) emit `hsection`, `hrow-name`, `chip`,
`chip-ok`, `chip-warn`, `chip-down`, `serif`, `mono`, `sub`. The mockup's
`mockup.css` — whose own header says it was "hand-copied from app.css so the
translation is a translation and not a reinvention" — was never applied.
Measured with a `document.styleSheets` walk, matching each element against every
rule:

```
.chip        -> ["*","*",".chip"]        (exists)
.chip-ok     -> ["*","*",".chip"]        (no .chip-ok rule exists)
.chip-warn   -> none                      (no .chip-warn rule exists)
.chip-down   -> none                      (no .chip-down rule exists)
.hsection    -> ["*","*"]                 (no rule exists)
.hrow-name   -> ["*","*"]                 (no rule exists)
.serif       -> ["*","*"]                 (no rule exists)
```

`grep desk src/gui/assets/*.css` returns **0 hits**. So every "chip" is a plain
run of text in the same grey, every "section head" collapses into the body, and
the five stages of the stage strip concatenate into one mashed run —
`sections[1].heading` literally reads
`"claims · doneoutline · donereview · donerender · done"`.

**Two corrections to my own first audit pass, recorded because a plan built on a
stale claim is worse than no plan:**

- **`stages` does not serialize as two-element arrays.** I first recorded
  `Vec<(Stage, StageState)>` as emitting `["claims", {"state":"done"}]`. The live
  API returns objects: `{"stage":"claims","state":"done","reason":null}`. The
  face must read `stage`/`state`/`reason` keys.
- **`delete_project` exists.** I first recorded "no `delete_project` in `src/`,
  no route". `src/desk.rs:358` defines it and it is tested
  (`src/desk.rs:2250`). What is missing is the *route* and the *face control* —
  the capability is unwired, exactly like `run_stages`.

## Direction lock

**The desk's job is to be believed, not to be looked at.** Everything here
serves one sentence the owner can act on: *what stands between this deliverable
and its end, and what do I do about it.* A surface that renders a refusal below
the fold, with no action beside it, has not done the job even if every pixel is
correct.

**The blocking state owns the top of the screen.** Refusals are the desk's whole
reason for existing; they go first, under the stage rail, not last under the
draft.

**The way out is always reachable.** Any screen with a primary action pins that
action to the viewport. A button 552px below the fold on a 700px screen is not a
control, it is a decoration.

**Colour carries state, and it is backed by a word.** A red pill says *why*. The
empty shell's failure was colour that never arrived; the fix is not "more
colour", it is colour that means one thing each, plus the word so colour is
never the only carrier.

**Tokens are copied, not invented.** The mockup copies `app.css`'s real themes.
The translation into app.css is a translation. A new token is a decision, not a
side effect.

**Fields the API computes get a home, or get deleted.** `coverage`, `overlap`,
`figures` and `escalated` are computed server-side at real cost. A field with no
surface is either a missing surface or a calculation nobody wanted.

## The design

`docs/plans/mockups/2026-11-05-desk-ux/desk.html` — one navigable page, 4 states
× 3 widths × 4 themes = 48 cells, each addressable:

```
?state=<shelf|deliverable|composer|empty>&w=<1440|1024|390>&theme=<paper|console|graphite|contrast>
```

**The shelf** is three zones: a left rail (all / needs you / by project / by
state), the shelf itself, and a standing right column, *what the desk owes you*,
which lists the refusals and gaps across every deliverable with a jump action.
Each shelf row carries its own state: a red left edge for refused, accent for
running, none for clean, and pills that name the state in words. Evidence reads
as one proportion bar (asserted / contested / unsourced) rather than three
identical chips. Coverage is a five-segment meter with its reason spelled out,
and the `escalated` flag is a pill. Empty and unbound desks are visibly
first-class-but-unstarted, not silently identical to finished ones.

**The deliverable** puts the stage rail at the top as five separate stacked
nodes — each with its own bead, its own fill (green done, red refused, accent
running) and its own label. Immediately below it, the gate: each refusal is a
row carrying its own assertion, the nearest sentence the extractor *did* find
with its overlap score (0.41), the canonical figure, and a fix action (*reword
it*, *add the figure*). Then the review, where every claim sits beside the exact
sentence it was read from, with its kind, confidence and source path. Outline
gaps render as a dashed hole in the outline itself, with the action that closes
them. The draft marks the refused figure inline. The end band pins to the
viewport bottom and says plainly *not ready to end — 2 refusals stand and
coverage is 2 of 5*.

**The composer** is a real form: required fields marked, per-source kind chips
(file / fact / url), a source list with remove, a shape select, a submit row that
names the fields still missing, and a pinned submit. Beside it, the four things
that will happen on submit, in the owner's language.

**The empty state** explains the benefit before the mechanism in three steps.

  instrument; it is also the better one.

  `[[label, node]]` sections) — the lesson that a row that renders fine can
  still be unpressable, so this plan pins the *press*, not the render.

## Acceptance criteria

- [ ] **C1 — the translation lands.** Every class `paintDesk`/`paintDeskProject`
      emit exists in `app.css` with the mockup's values: `hsection`, `hrow-name`,
      `chip`, `chip-ok`, `chip-warn`, `chip-down`, `serif`, `mono`, `sub`, plus
      the new desk rules. `grep desk src/gui/assets/*.css` is non-zero, and a
      test walks `document.styleSheets` asserting that no element the desk paints
      resolves only through a bare `*` rule. *This is the headline defect and the
      first thing that lands.*
- [ ] **C2 — the three zones.** The desk page renders a project rail, the shelf,
      and the owes-you column at ≥1200px; the rail collapses to a scrolling
      strip and the owes-you column stacks below at <1200px; measured, no
      sideways overflow at 1440/1024/390.
- [ ] **C3 — the shelf row carries its state.** A refused desk is
      distinguishable from a clean one **without opening it**: a left edge and a
      pill naming the count. A desk with no stages walked is distinguishable from
      one that finished. Pinned by a case that builds both and compares.
- [ ] **C4 — colour means one thing each.** `chip-ok`, `chip-warn`, `chip-down`
      each resolve to their own `--ok`/`--warn`/`--down` token (measured:
      distinct computed colours, per theme), and every state also carries a word,
      so the state survives a colour-blind reader.
- [ ] **C5 — the gate owns the top.** On the deliverable, the refusal list
      renders directly under the stage rail and above the review. Measured at
      1440×700: the gate's top is < 700 and the review starts below it.
- [ ] **C6 — the way out is reachable.** The end band and the composer's submit
      pin to the viewport bottom (`position: sticky; bottom: 0`), with no
      `overflow: hidden` ancestor creating a dead scrollport. Measured at
      1440×700: the primary action's bottom ≤ 700 on every state that has one.
- [ ] **C7 — the stage rail is five elements.** Five separate nodes, each with
      its own bead fill by state and its own label; no concatenated text run.
      Measured: five distinct boxes with non-overlapping labels, and the stage
      names are not read as one string.
- [ ] **C8 — the refusal offers a fix.** Each refusal row carries an action
      that reaches the thing that closes it (open the source, reword the claim,
      add the figure). Pinned by a case asserting the control exists and its
      press names the refusal it addresses.
- [ ] **C9 — the computed fields get a surface.** `coverage.score` (as a meter,
      with `reason` in words), `coverage.escalated` (as a pill),
      `refusals[].overlap` (beside the near-miss sentence),
      `number_refusals[].canonical`, `claim.kind`, `claim.confidence`,
      `sources[].title`/`fetched_at`, `created`/`updated`. Each one rendered
      somewhere a reader can see it; asserted by a case per field.
- [ ] **C10 — the face can advance a desk.** `POST /api/desk/<slug>/run` (or the
      shape the bridge prefers) exposes `run_stages`, and `POST
      /api/desk/<slug>/end` exposes the distil step, so a desk can be walked and
      ended from the face. Pinned by a route test and a live walk. **Until this
      lands the end button must not pretend to be a control** — it says why it
      cannot act.
- [ ] **C11 — a desk can be removed.** A `POST /api/desk/<slug>/delete` route
      wires the existing `desk::delete_project`, and the face carries a
      destructive control behind the standing destructive gate. Pinned by a
      route test plus a case that the control is held, not silent.
- [ ] **C12 — a corrupt desk is named, not dropped.** `projects()` surfaces a
      project that fails to parse as an error row rather than `.ok()`-ing it
      away. Pinned by a test that writes malformed JSON into a desk directory and
      asserts it appears, by slug, with its error.
- [ ] **C13 — rows are operable.** Shelf rows and cards are real buttons (or
      carry `tabindex` + `role` + a key handler), reachable by Tab and pressable
      by Enter/Space. Pinned by a harness case, not by inspection.
- [ ] **C14 — the composer validates.** A submit missing `name` or `claim`
      states which field is missing and mutates nothing. A duplicate slug is
      named. Pinned by cases for both.
- [x] **C15 — the mockup matrix.** `docs/plans/mockups/2026-11-05-desk-ux/` holds
      the navigable page and its screenshots, and the measurement passes on all
      48 cells: no overflow, no clipped text, no target under 24px, ink ≥ AA
      (measured min 4.59:1), gate above the fold, primary action in the fold.
      *Met:* `desk.html` + `README.md` + 48 screenshots; measured **48/48 cells
      pass** — 0 overflow, 0 clipped text, 0 sub-24px targets, min ink **4.59:1**,
      12/12 gate states above the fold, 48/48 primary actions in the fold, 48/48
      cells URL-addressable. Three real defects were found by the instrument and
      fixed before green: `.srcs` used an implicit grid column and pushed rows
      +173px past the device edge at 390px; a done bead's white `✓` on `--ok`
      measured **2.36:1** in console/graphite; and `position: sticky` never
      engaged because `overflow: hidden` on the device made it the sticky
      scrollport. A fourth — the deliverable's primary action at
      `bottom: 1419` against a 700px viewport, reproducing the shipped defect —
      was caught only because the fold assertion was added after the first green
      run.
- [ ] **C16 — the harness.** New cases pin C2-C4, C7-C9, C13-C15; `node
      tests/face/harness.mjs` is green with a higher case count than today.
- [ ] **C17 — the docs.** `docs/features/desk.md` describes the surface as
      built, `FUNCTIONAL-SPECIFICATIONS.md` carries the desk passage,
      `TECHNICAL-DOCUMENTATION.md` carries the new routes, and
      `docs/known-issues.md` carries the fifteen audit findings as KI rows with
      their evidence.
      *Partly met:* the ledger half is done — all fifteen findings are filed as
      **KI-433 … KI-445** (thirteen rows; findings 2+3 merge into KI-439 and
      4+5 merge with it too, and 15 folds into KI-443), and
      `python3 scripts/ki_ledger.py docs/known-issues.md` reports 431 → 444
      rows, zero cell-count problems. The three prose passages
      (`docs/features/desk.md`, `FUNCTIONAL-SPECIFICATIONS.md`,
      `TECHNICAL-DOCUMENTATION.md`) are **not** written, because they must
      describe the surface *as built* and the surface is not built yet. Unticked
      deliberately: a criterion ticked on one of its clauses is a lie the next
      audit cannot see.
- [ ] **C18 — the gate.** `cargo fmt --check`, `cargo clippy --all-targets -D
      warnings`, `cargo build --release`, `cargo test` — exit codes read on the
      cargo invocation itself, never through a pipe.
- [ ] **C19 — the live proof and delivery.** Driven on the scratch home with the
      release binary: a refused desk shows its refusal above the fold with a
      working fix action, the shelf distinguishes it without opening it, and a

      replaced through a new inode, the agent restarted, and the served `app.js`
      grepped for the desk's markers with the process start time compared against

## Out of scope

- Any change to the extraction spine, the document law, or the number guard —
  the desk's *judgments* are sound; this plan is about their surface.
- A new persistence mechanism or store format. `stages` stays
  `Vec<(Stage, StageState)>`; the face learns to read what it emits.
- Rich-text or in-place editing of the draft.
- Real-time stage streaming. The walk is request/response; a progress stream is
  its own plan if the owner wants to watch a long walk.
- A cross-surface artifact registry.
- Any new token. If a value is not already in `app.css`, it is a decision this
  plan does not make.
- The `#/desk` routing, the GROUPS row, or the icon keys — already shipped and
  not this plan's subject.

## Risks

- **The translation is bigger than it looks.** The desk's markup was written
  against a stylesheet that never arrived, so it was never *constrained* by one.
  Some of its structure will need to change shape as the CSS lands, not just gain
  rules. Budget for rewriting the painters rather than only adding rules.
- **C10's routes are the load-bearing increment.** Without a face-side walk the
  end button cannot honestly be a control, and the surface stays a viewer. If
  C10 slips, C6 still applies but must say *not ready* rather than *end*.
- **A pinned action band can cover content.** Sticky furniture eats viewport on
  a 700px screen. The measurement must assert that the last section is not
  permanently hidden behind the band.
- **Copy that flatters.** "It reads the sources and refuses to call the work
  done" is a promise about behavior. Where the face cannot yet keep it (no walk
  route), the copy must not imply it can.
