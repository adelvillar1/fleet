The owner's rulings (2026-11-08), on the LearnHarness comparison dive: *"learning needs to also be treated as project knowledge, there is no reason for having all this information and not treating it that way, it could also feed the self-improvement system."*

**Why:** a learning record kept in its own store would be the silo the house's other rulings refuse (the memory substrate is the one knowledge home; the calibration stream is the one evidence home). The owner's instinct is the same one behind the dream pass and the capability library — information the system already holds should flow to the systems that consume it.

**How to apply:** (a) The knowledge graph rides the memory substrate — propositions are facts (a `proposition` type), chains are facts carrying a `premises` field (the joint-premise hyperedge the pairwise recall graph lacks), provenance is the fact's `source`, practice outcomes are facts; the extraction pipeline writes through the one writer, so recall, the dream pass, and the calib rows apply unchanged. (b) The friction feeds the loop: the learning events (probe answers, checks, practice outcomes) join the calib stream as rows the demand map reads; the recurring confusions feed the clustering beat's shape proposals (owner-applied `improve` proposals, as C1 already lands); the friction itself is proposal feedstock ("the confusion about X says the docs lack Y"). The dream pass reads the teaching prose for the extraction and the learner's records for the confusions in one pass. (c) The first plan's scope: the lesson session kind's records ride the substrate from the start — the probe answers and checks are facts and calib rows, not a side format; the frontmatter schema work (the `proposition` type, the `premises` field) goes through the same `Remember::parse` path. (d) The capability feed (the third ruling, 2026-11-08): the learning record's friction also names what the PROJECT lacks, and the lack's kind picks the surface — a lesson needing an expertise the project has no one in signals a PERSONA (the roles module, the huddle's `author_persona` precedent); a recurring procedure signals a SKILL (the self-authoring drafter already files owner-gated drafts from sessions; teaching prose is skill-shaped feedstock); friction no tool addresses signals a TOOL (the `improve` proposal store is its backlog); a procedure repeating across lessons signals a WORKFLOW (the cron's scheduled runs, the plan templates, the huddle workflows). The huddle's capability-gap card is the precedent — the signal already exists in one surface; the learning record generalizes it. Every proposal lands through its surface's own gate (the role overlay's approval, the drafter's owner-gated drafts, the improve store, the cron), never a silent self-application.
