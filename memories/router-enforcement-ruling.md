The owner's architecture ruling: fleet is a self-contained harness in the deepseek-harness tradition where everything is a plugin, which is why the router's parts are plugin config loaded from FLEET_HOME and validated on load rather than a separate component consulted at run time. The pin's stated purpose is quota - it lets the owner use a specific provider when a large unused quota sits on a vendor - and the router then picks that provider's model per the judged workload. The reserve cannot serve silently: allowPayg false is ported as policy, so a declared-but-untargeted provider never answers unless the walk reaches it by name. Judging walks the internal in-process path (the vendored sys1 lane over MCP stdio), never an external CLI.
